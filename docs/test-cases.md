# CampusEvent 验收与回归测试用例

| 项 | 值 |
|---|---|
| 版本 | v1.0（对应 `baseline-v1`） |
| 用途 | 初始版本验收（C1–C10）+ 变更版本回归（全部重跑） |
| 执行方式 | 手工（UI）+ 自动化（`tests/`，unittest 与 HTTP 脚本） |
| 编写 | 周静文　242806010206　24计科2班 |

> 约定：`S1`=学生A（s001）、`S2`=学生B（s002）、`S3`=学生C（s003）；`ADM`=管理员。
> 「已通过数 / 待审核数 / 剩余名额」均指某活动维度。

---

## 1. 初始版本验收用例（C1–C10）

### C1 创建直接报名活动
| 项 | 内容 |
|---|---|
| 操作 | `ADM` 创建活动：标题「羽毛球社招新」、类型体育、未来时间、容量 2、报名方式=直接 |
| 预期 | 创建成功，返回 `activity_id`；列表可见；剩余名额 = 2 |
| 判定 | 详情页显示容量 2、剩余 2，报名按钮可用 |
| 自动化 | `test_activity_create_direct` |

### C2 直接报名自动通过并通知
| 项 | 内容 |
|---|---|
| 操作 | `S1` 报名 C1 的活动 |
| 预期 | 报名状态 `APPROVED`；已通过数=1、剩余=1；`S1` 消息列表新增 1 条「报名已通过」 |
| 判定 | 状态与统计一致；消息存在且 `is_read=false` |
| 自动化 | `test_register_direct_auto_approve` |

### C3 重复有效报名被拒绝
| 项 | 内容 |
|---|---|
| 操作 | `S1` 再次报名同一活动 |
| 预期 | 返回 409；报名记录数不变（仍 1 条）；已通过数仍 1 |
| 判定 | 错误码与提示正确；无第二条有效报名 |
| 自动化 | `test_register_duplicate_rejected` |

### C4 名额上限
| 项 | 内容 |
|---|---|
| 操作 | `S2` 报名（此时剩余 1）→ 成功；`S3` 再报名 |
| 预期 | `S2` 变为 `APPROVED`（剩余 0）；`S3` 返回 409「名额已满」 |
| 判定 | 已通过数=2=容量；`S3` 无记录 |
| 自动化 | `test_register_capacity_full` |

### C5 审核型报名进入待审核
| 项 | 内容 |
|---|---|
| 操作 | `ADM` 创建审核型活动（容量 2）；`S1` 报名 |
| 预期 | 状态 `PENDING`；已通过数=0、待审核数=1、剩余=2（待审核不占名额） |
| 判定 | 统计三项数值正确 |
| 自动化 | `test_register_review_pending` |

### C6 批准待审核报名
| 项 | 内容 |
|---|---|
| 操作 | `ADM` 批准 `S1` 的待审核报名 |
| 预期 | 状态 `APPROVED`；已通过数=1、待审核数=0、剩余=1；`S1` 新增一条审核通过消息 |
| 判定 | 状态、统计、消息三者一致 |
| 自动化 | `test_approve_pending` |

### C7 拒绝待审核报名
| 项 | 内容 |
|---|---|
| 操作 | `S2` 报名审核型活动；`ADM` 拒绝 |
| 预期 | 状态 `REJECTED`；已通过数不变；`S2` 收到拒绝消息 |
| 判定 | 状态与消息正确；`S2` 可再次申请（新建记录） |
| 自动化 | `test_reject_pending` |

### C8 批准时名额已满
| 项 | 内容 |
|---|---|
| 操作 | 审核型活动容量 2：`S1`、`S2` 已通过占满；`S3` 提交待审核；`ADM` 批准 `S3` |
| 预期 | 批准失败（409「名额已满」）；`S3` 保持 `PENDING`；已通过数仍 2 |
| 判定 | 状态未变；无超卖 |
| 自动化 | `test_approve_when_full` |

### C9 取消报名
| 项 | 内容 |
|---|---|
| 操作 | `S1` 取消一条 `PENDING`；`S2` 取消一条 `APPROVED` |
| 预期 | 两者状态均变为 `CANCELLED`；已通过数 −1（针对 S2）；待审核数 −1（针对 S1）；统计同步 |
| 判定 | 状态与统计一致；取消后可再次报名成功 |
| 自动化 | `test_cancel_registration` |

### C10 重启后数据一致
| 项 | 内容 |
|---|---|
| 操作 | 停止服务 → 重启 → 查询活动、报名、消息 |
| 预期 | 数据与重启前完全一致；统计不变 |
| 判定 | 逐字段比对快照 |
| 自动化 | `test_persistence_after_restart` |

## 2. 边界与异常用例（回归必跑）

| 编号 | 场景 | 预期 |
|---|---|---|
| E1 | 活动开始后再报名 | 409「活动已开始」，无记录 |
| E2 | 取消后再报名 | 允许，生成新记录；旧记录保留 `CANCELLED` |
| E3 | 非本人取消他人报名 | 403，状态不变 |
| E4 | 非管理员调用创建/审批接口 | 403 |
| E5 | 创建活动容量 0 或负数 | 400，参数校验失败 |
| E6 | 创建活动报名方式非法 | 400 |
| E7 | 删除有报名的活动（软删除） | 列表/详情不可见；历史报名与消息仍在；不可再报名 |
| E8 | 通知写入失败（注入异常） | 报名/审批结果不回滚；`notify_failures` 有 1 条；接口成功 |
| E9 | 10 并发报名容量 5 的活动 | 成功 ≤ 5，无超卖（NFR2） |
| E10 | 管理员重复批准同一条 | 第二次 409，状态不变 |
